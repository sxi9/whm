# HST Panel — wave-1 build plan (binding contract + unit split)

Companion of `hst-panel-user.md` (the design of record). This is the plan the 2026-10-31 session prepared for the first build wave of the customer side; it was not launched (the account hit its spend limit during the Issue-2 integration round). Any engineer or agent run can build from it: the **contract** below is binding for every unit so that concurrently built units agree on names, and the **units** are disjoint file lists. Order: Foundation (H0 + H1) → Sections (H2, H3a, H3b, H4) → Flow (H5) → adversarial review (three lenses) → two refuters per finding → one fix round grouped by file ownership → the full gate (`npm test`, builds, monolithic boot on a random port, `e2e/ui-check.cjs`) → screenshots.

Ground rules for every unit: CLAUDE.md conventions (`exec(bin, argv[])` only, zod on every input, `ctx.assertAllowedPath` on every path, audit rows on mutations, `CapabilityError` when a daemon is missing); edit only the files the unit owns; build against the contract and report gaps; run only the unit's own test files; never execute a privileged op for real in the dev container (mock `exec`/`hasBinary`; server tests use the mock agent through `bootstrap()` as in `server/test/account-functions.test.js`).

## 1. Contract (binding, wave 1)

- **Principal:** users.role = 'user' with users.account_id (migration server/src/db/migrations/040_hst-user.sql, created by H0; guarded ALTER like the other 0NNb migrations). middleware/auth.js already loads the user row for the session: H0 adds account_id to USER_COLUMNS and exposes req.user.accountId. Impersonation: POST /api/accounts/:username/impersonate (root, or reseller owning the account) stores { accountId, actorUserId, until } in the session (req.session.impersonation) and in hst_sessions_impersonation; DELETE the same path ends it; GET /api/auth/me returns user.hst = { accountId, username, domain, impersonating: { by, until } | null } for a user principal or an impersonating admin.
- **RBAC:** middleware/rbac.js exports requireUser = (req, res, next) → allows role 'user' with an accountId, or root/reseller with req.session.impersonation; everything else 403 'user_required'. Service: server/src/services/hst.js → createHstService(ctx) attached as ctx.hst with accountOf(req) (the accounts row { id, username, domain, home, package, owner, suspended, suspend_reason, ... } resolved ONLY from req.user.accountId or the impersonation record; throws HttpError(403, 'not_an_account') otherwise; throws HttpError(423, 'account_suspended') when suspended and the caller is not an impersonating admin), requireFeature(account, feature) (feature list of the account's package via ctx.packages / feature_lists; throws HttpError(403, 'feature_disabled')), limits(account) ({ package snapshot, usage: disk/bandwidth/inodes from ctx.accountInfo }), ensureForAccount(account, { password, email }) (creates the panel user <username> with role user, account_id, must_change_password false; idempotent), removeForAccount(account), lockForAccount(account) (sessions end on suspension), impersonate(username, actor, req), loginHistory(account), audit helper hstAudit(req, action, target, args).
- **Routes:** one router per section in server/src/routes/hst/<section>.js exporting async register(ctx) → { path: '/hst/<section>', router } (same contract as routes/categories/*; H0 makes routes/index.js discover routes/hst/*.js after requireAuth, never public). Every hst router applies requireUser first and resolves the account with ctx.hst.accountOf(req) inside each handler; never trust an account/username/path from the request to pick the tenant. Validation with validate() from middleware; envelope { data, meta }; long operations 202 { data: { job } } with created_by = req.user.id so GET /api/hst/jobs/:id (H0, mirrors /api/system/jobs/:id + the SSE stream, scoped to the caller's own jobs) works; audit action names 'hst.<section>.<verb>'.
- **Client:** client/src/hstNav.js exports SECTIONS = [{ slug, label, icon (lucide name resolved through client/src/icons.js), pages: [{ key: '<section>/<page>', slug, label, description }] }] and HST_PAGES (flattened, each with path '/hst/<section>/<page>'); client/src/pages/hst/registry.js discovers pages with import.meta.glob('./*/*.jsx') keyed '<section>/<page>' (H1 creates both and the shell client/src/hst/{HstLayout,HstSidebar,HstTopBar}.jsx, the dashboard client/src/pages/hst/home/dashboard.jsx and the /hst routes in client/src/router.jsx; Layout.jsx sends role 'user' to /hst and HstLayout sends a non-user without impersonation to /). Section pages default-export a component ({ page }) and use the component kit (client/src/components/*: DataTable, Form, Modal/useConfirm, ProgressLog/useJobRunner, Common: Card/Badge/EmptyState/CapabilityNotice, Toast) and the api client (client/src/api). Every table gets a card layout under 720 px (class 'hst-cards' pattern from H1's hst.css), every destructive action confirms with the object's name, every long operation streams its job log inline, every empty state explains the page.
- **Agent ops inside the home run as the account:** exec('runuser', ['-u', username, '--', ...argv], { env: { HOME: home } }) like web.docroot.ensure in agent/src/ops/web.js (asUser helper); root never reads or writes inside the home. Paths: absolute, under the account's real home (fs.realpathSync of the home from /etc/passwd + lexical check + no component may be a symlink pointing outside — resolve with realpath and compare), limits: editor 4 MB, upload 512 MB (chunked), download 512 MB (chunked), archive extract as the user with --no-same-owner and device/special entries refused by listing first.
- **Tests:** server/test/hst-<section>.test.js — for every route: a user principal of account A (helper in server/test/helpers/hst.js created by H0: createHstAccount(app, { username, domain, password }) → { cookie/agent for the user, account }) can read/change only A; the same requests against B's ids/usernames/paths/jobs answer 403/404 and change nothing; impersonation by root works and is audited; a suspended account's user gets 423. agent/test/<family>.test.js — schema rejections, path escape refusal, runuser argv shape. client/test/hst-*.test.jsx — render with empty data, actions call the right routes.
